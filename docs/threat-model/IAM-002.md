
# IAM-002 — Unauthorized STS Role Assumption

## 1. Threat Summary

A fictional AI research assistant operates as an Amazon ECS task
using an assigned IAM task role.

An attacker who compromises the workload attempts to assume a
separate, more privileged research administration role using
AWS Security Token Service (STS).

## 2. Protected Assets

- Privileged research administration role
- Restricted synthetic research datasets
- IAM role trust relationships
- Temporary STS credentials

## 3. Attacker Starting Position

The attacker has obtained code execution within the compromised
ECS application workload.

The attacker can attempt AWS API operations using the workload's
available IAM identity.

The attacker does not initially possess administrator credentials.

## 4. Attack Path

1. Compromise the ECS application workload.
2. Identify a privileged IAM role.
3. Invoke `sts:AssumeRole` targeting that role.
4. Exploit permissive caller permissions and target-role trust.
5. Obtain temporary credentials for the privileged role.
6. Attempt access to restricted research resources.

## 5. Trust Boundary

TB-04: Workload identity to privileged role assumption.

Crossing this boundary requires authorization from both the
calling identity and the target role's trust configuration.

## 6. Baseline Weakness

The modeled baseline permits the application workload to request
assumption of a privileged role, and the target role trusts the
workload identity.

## 7. Proposed Security Controls

- Restrict `sts:AssumeRole` to explicitly approved target roles.
- Remove unnecessary role-assumption permissions from the workload.
- Restrict target-role trust to authorized principals.
- Monitor role-assumption events using CloudTrail.
- Apply additional controls where appropriate, such as conditions
  and organizational guardrails.

## 8. Validation Plan

Create synthetic baseline and hardened IAM policies.

Extend offline evaluation to account for both caller permission
and target-role trust.

Demonstrate unauthorized role assumption under the baseline and
its prevention under the hardened configuration.

Add automated regression tests and preserve their results.

## 9. Scope and Limitations

All resources and identities are fictional.

No AWS accounts, credentials, or live STS operations are used.

Offline simulation does not establish production AWS enforcement.
