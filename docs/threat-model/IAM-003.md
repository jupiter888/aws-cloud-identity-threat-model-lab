
# IAM-003 — Unauthorized Secrets Manager Access

## 1. Threat Summary

A fictional AI research assistant operates as an Amazon ECS
task using an assigned IAM task role.

An attacker who compromises the application workload attempts
to retrieve secrets beyond the application's authorized scope.

## 2. Protected Assets

- Application-specific synthetic secret
- Research administration synthetic secret
- AWS Secrets Manager resource permissions
- ECS workload identity

## 3. Attacker Starting Position

The attacker has obtained code execution within the ECS
application workload.

The attacker can attempt AWS API operations using the
workload's available IAM identity.

No real credentials or secret values are used.

## 4. Attack Path

1. Compromise the ECS application workload.
2. Identify accessible Secrets Manager resources.
3. Invoke `secretsmanager:GetSecretValue`.
4. Exploit excessive IAM permissions.
5. Attempt retrieval of an unauthorized synthetic secret.

## 5. Trust Boundary

TB-03: Application workload to protected AWS resources.

## 6. Baseline Weakness

The baseline workload identity policy grants
`secretsmanager:GetSecretValue` across all resources.

This exceeds the application's intended authorization scope.

## 7. Proposed Security Controls

- Restrict secret retrieval to the application-specific ARN.
- Apply least privilege to the ECS task role.
- Separate application and administrative secrets.
- Monitor Secrets Manager access using CloudTrail.
- Evaluate resource policies and applicable organizational
  controls in a production implementation.

## 8. Validation Plan

Create synthetic baseline and hardened IAM policies.

Use the existing offline identity-policy evaluator to compare:

- Access to the approved application secret.
- Access to the restricted administration secret.
- Access to an unrelated secret.

Add automated regression tests and preserve evidence.

## 9. Scope and Limitations

All identities and resources are fictional.

No real secret values, AWS credentials, or live API requests
are used.

The offline evaluator does not reproduce the complete AWS
authorization model or prove production enforcement.
