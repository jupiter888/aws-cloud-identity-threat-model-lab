# IAM-003 — Unauthorized Secrets Manager Access

## 1. Threat Summary

A fictional AI research assistant is represented as an Amazon ECS task using an assigned IAM task role.

An attacker who compromises the application workload attempts to retrieve secrets beyond the application's intended authorization scope.

The ECS application and AWS resources are architectural representations. Policy artifacts and selected authorization behaviors are implemented and tested offline.

## 2. Protected Assets

- Application-specific synthetic secret.
- Research administration synthetic secret.
- AWS Secrets Manager resource permissions.
- ECS workload identity.

## 3. Attacker Starting Position

The attacker is assumed to have obtained code execution within the fictional ECS application workload.

The attacker can attempt AWS API operations using the workload's available IAM identity.

No real credentials or secret values are used. Application exploitation and credential extraction are not demonstrated.

## 4. Attack Path

1. Compromise the ECS application workload.
2. Identify Secrets Manager resources.
3. Invoke `secretsmanager:GetSecretValue`.
4. Exploit excessive IAM permissions.
5. Retrieve an unauthorized secret if all applicable authorization requirements are satisfied.

The offline lab evaluates selected policy decisions. It does not retrieve secret values or execute this attack against AWS.

## 5. Trust Boundary

**TB-03 — Workload Identity to Data Resources**

The application workload must not retrieve secrets beyond its explicitly authorized scope.

## 6. Baseline Weakness

The baseline identity policy grants `secretsmanager:GetSecretValue` against all resources.

This exceeds the application's intended need to retrieve its own application secret.

An identity-policy allow does not independently establish real AWS access. Other applicable policies and encryption-key permissions may affect the outcome.

## 7. Security Controls and Implementation Status

### Implemented in the Offline Lab

- A baseline identity policy demonstrates excessive secret-retrieval permissions.
- A hardened identity policy restricts `secretsmanager:GetSecretValue` to the fictional application secret ARN pattern.
- The hardened policy does not grant secret deletion or retrieval of the modeled administration and unrelated secrets.
- Automated regression tests compare selected permitted and prohibited requests.

The hardened resource pattern is:

    arn:aws:secretsmanager:eu-central-1:111122223333:secret:ari/application/config-??????

The six question marks match a six-character suffix in the modeled ARN.

Policies:

- [Baseline policy](../../policies/iam-003-baseline.json)
- [Hardened policy](../../policies/iam-003-hardened.json)

### Architectural Intentions and Proposed Controls

- Separate application and administrative secrets and their access permissions.
- Monitor Secrets Manager access using CloudTrail.
- Evaluate resource policies, encryption-key permissions, and applicable organizational controls for a production implementation.
- Establish secret rotation, secure application-side handling, and runtime exposure protections.

These runtime, monitoring, and production controls are not implemented or validated in this lab.

## 8. Validation and Evidence

Six automated regression tests pass using the project's limited offline identity-policy evaluator.

The tests verify that:

- The baseline permits retrieval of the approved application secret.
- The baseline permits retrieval of the restricted administration secret.
- The hardened policy preserves retrieval of the approved application secret.
- The hardened policy implicitly denies retrieval of the restricted administration secret.
- The hardened policy implicitly denies retrieval of an unrelated secret.
- The hardened policy implicitly denies deletion of the approved application secret.

## 9. Scope and Limitations

All identities and resources are fictional.

No real secret values, AWS credentials, or live API requests are used.

A compromised workload may still retrieve and misuse its legitimately authorized application secret.

The evaluator implements a limited subset of IAM identity-policy authorization semantics.

Matching conditional statements and statements containing `NotAction` or `NotResource` are flagged as `UNSUPPORTED` rather than treated as definitive authorization decisions.

`UNSUPPORTED` indicates an indeterminate offline result, not an AWS access-denied decision.

IAM conditions, resource policies, service control policies, permissions boundaries, session policies, and other applicable authorization mechanisms are not comprehensively modeled. Some unsupported constructs may remain unrecognized.

KMS permissions and encryption-key access are not evaluated.

Secret rotation, application-side handling, and runtime exposure protections have not been implemented.

CloudTrail monitoring and alerting remain proposed.

**Implementation status:** Threat modeled; resource-scoped policy mitigation implemented; six offline regression tests passing.

Production effectiveness is not established.
